# The 128K version

The main differences between the 128K version and the 48K version.

In the 128K version: 
* both parts are in memory at once
* music plays under interrupts
* the handover from part 1 to part 2 has been rewritten in a way that breaks it.

## Memory layout

The shared 48K area (banks 5 and 2, 4000-BFFF) is laid out as in [memory_map.md](memory_map.md), apart
from BC00-BFFF (see below). C000-FFFF is banked:

| Bank | Contents |
|------|----------|
| 0 | Part 1's C000-FFFF: interpreter state, variables, template table (now at C0CA), templates, witch and scenery sprites |
| 1 | Part 2's C000-FFFF, laid out as in the 48K version (template table at C0DC, templates from C200) |
| 3 | AY music player (C000-CA8B) |
| 4 | Picture decompressor (C000-E903). It draws picture 1, 2 or 3 into the screen. |
| 6, 7 | Not used |

## Dynamic objects

In part 1, the list is the same as in the 48K version, except for two dummy entries inserted at ids
36 and 37:

```
36: 80 00 00 00 00 00
37: 80 00 00 00 00 00
```

This causes the difference described in [handover.md](handover.md) - if you drop the sword and the wand
in the 128K version of part 2, they turn into a table and a stool, rather than 2 skeletons.

There is also a change in the timing of when various templates execute, meaning that the objects
are corrupted immediately on entering part 2. So the 128K version can't be completed.

## Music

The player in bank 3 is a three-channel AY player that advances the tune every 8 interrupts.

## Engine code changes

There are various changes to the engine to keep interrupts enabled so the music keeps playing.

## Pictures (bank 4)

Bank 4 holds three full-screen pictures and the routine that draws them (C000). The routine reads the
picture number from C002 (set by BF43, BF47 or BF4B). Renders are in [128k_pictures](128k_pictures).

| No. | Data | Picture | Shown by |
|-----|------|---------|----------|
| 1 | C12C, 1508 bytes | Title screen: "Fairlight - A Trail of Darkness", Bo Jangeborg, N. Österlin, The Edge logo | No template. Probably the loader, but this is not confirmed. |
| 2 | D635, 08B4 bytes | "Sailing Across": a ship in a storm | Part 1, template 95 (end of part 1) |
| 3 | DEEA, 09CA bytes | "THE END?": a cloaked figure against a burning sky | Part 2, template 87 (end of the game) |

Format: the pictures are stored one after another, starting at C12C. Each picture starts with a 2-byte
length, and the next picture starts at the length word's address + 1 + the length. After the length come
three header bytes:

- the first third of the screen (0-2);
- the number of thirds to draw (1-3);
- flags. With bit 0 clear, the bitmap is stored column by column (32 columns, each from the top line of
  its first third downwards). With bit 0 set, it is stored line by line.

All three pictures use third 0, 3 thirds, and column order.
The attributes follow the bitmap, in normal order. The data is run-length encoded: `00 n v` means n copies
of v (n = 0 means 256), and any other byte is a literal. If C003 or C004 is not FF, it overrides the
first-third or number-of-thirds byte. The routine sets both back to FF when it finishes.

## Graphics

The magic carpet's floor sprite is empty, so it doesn't display properly (except when you are riding it).
